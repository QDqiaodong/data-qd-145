# 现金核销对账 (cash-reconcile)

`cash-reconcile` 把一次完整的银行事件快照（来款、核销批次、退票流水）处理成一份
可追溯的现金核销报告。`--ledger` 是已有 v2 账簿的**只读快照**，`--source` 是本次
完整银行事件快照；每次运行从零重放全部事件，不创建新的持久账簿，不改动读数、
原账簿、冻结发票或原价目表，也不重算计费和迟到更正。v1 单期调用与
`ingest` / `status` / `close` / `aid-plan` / `storage-plan` 入口完全保留。

```sh
tariff-rating cash-reconcile --ledger fixtures/cash_ledger.json \
    --source fixtures/cash.json --output run/cash-report.json
```

## 冻结发票只读取数（ledger.py 新接口）

`ledger.load_snapshot(path)` 以只读方式解析 v2 账簿：只解析持久事实，**不触发
读数链重算**、不构建派生视图、不写回文件，返回状态与账簿原始字节 SHA256
（随报告保留）。账簿文件上限 64MB，符号链接拒绝。

`ledger.frozen_invoice(state, account, period, invoice_sha256, currency)` 从
`closed` 中提取一份所选冻结发票：

- 只取 `closed` 中的 invoice 原文；移去 `invoice_sha256` 字段后按本仓
  canonical/SHA 规则（`common.sha256_hex`，即关账时计算该字段的同一规则）重算，
  与发票内存储的 SHA 及请求中的 SHA 双重核对——所选冻结发票被篡改（改动金额、
  调整项或 SHA 字段本身）都会被检测并拒绝。不要求支持人为损坏的账簿。
- 再核对请求中的 `account`、`period`（接受 `YYYY-MM` 或期序号，规范化为
  `YYYY-MM`）与 `currency`。
- **真实应收是已含调整的 `invoice.total`**：不把 `own_total` 当应收，也不再次
  加减 `received_adjustments`。
- 即使当前读数已令该源期 held 或 pending，冻结发票仍可收款：接口只凭冻结
  凭据，绝不用当前派生状态替代它。

## 输入快照

顶层字段恰好为 `currency invoice_refs events`：

- `currency`：沿用现有标识规则，且必须与每份所选发票的冻结币种一致；无换汇。
- `invoice_refs`：最多 60 项，每项恰好 `id account period invoice_sha256
  due_rank`。`id` 唯一并沿用现有标识规则；`due_rank` 为 0..10^9 整数；引用必须
  唯一对应一份已关账发票，同一发票不可换 id 重复引用；所选发票应收均为非负
  整数且合计不超过 10^24。**发票优先序按 `(due_rank, id)` 升序。**
- `events`：有语义顺序的数组，最多 200 项，各事件 `id` 全局唯一：
  - `receipt`：恰好 `id kind amount eligible`。`amount` 为 1..10^18 整数；
    `eligible` 为不重复的已定义发票 id 数组（允许空数组）。最多 60 笔来款，
    所有 `eligible` 长度之和不超过 600。
  - `return`：恰好 `id kind receipt_id amount`。`receipt_id` 必须指向此前
    （事件顺序上更早）的 receipt；`amount` 为正整数且不超过该来款尚未退回的
    本金（原额减去此前累计退票）。
  - `settle`：恰好 `id kind`，最多 10 次；没有 settle 也合法。

只允许整数最小货币单位：无浮点、无换汇、无逐货币单位展开。拒绝重复 JSON 键、
未知字段、重复身份/引用、布尔伪整数、非法事件或 SHA 不符；任何输入或计算失败
退出 2 并保留旧报告（输出原子替换、拒绝符号链接、输出不得覆盖 source 或
ledger）。source 上限 8MB。

## 银行资金生命周期

- `receipt`：增加该笔来款的未核销现金。
- `settle`：把本轮求出的核销切片**正式入账**；后续轮次不得挪动此前仍有效的
  切片。
- `return`：先冲减**同一笔**来款的未核销现金；剩余退票额再按原 settle 事件
  逆序、同一 settle 内发票 id 降序，逐片撤销该来款的有效核销（允许部分撤销），
  并重开相应发票欠款。退票不能冲减别笔来款，不能重置整张发票的已收金额；每个
  原切片、累计撤销额与撤销来源事件都保留在报告中。
- 每个事件之后均满足两类守恒：逐来款 `原本金 = 累计退票 + 未核销现金 +
  有效核销`；逐发票 `冻结应收 = 有效核销 + 剩余欠款`。

## 受限核销（每次 settle）

仅使用此刻各 receipt 未核销现金与各发票剩余欠款，在 eligible 边上分配非负整数
金额；允许拆分来款、部分支付发票；不可透支、串用币种或把将来的事件提前使用。
所有合法分配按三级目标取全局精确最优：

1. 本轮核销总额最大；
2. 按发票优先序字典序最大化本轮逐发票核销额；
3. 字典序最大化本轮分配矩阵（先按 receipt 在 events 中的出现顺序、再按发票
   优先序展平，禁止边视为 0）。

求解不逐来款贪心、不枚举金额或全部矩阵、结果不依赖集合遍历顺序（见下节）。

## 切片谱系的双向联动

两项职责共用同一份切片谱系：上一轮核销矩阵决定下一次 return 具体重开哪些发票
（撤销顺序只作用于已入账切片）；return 的撤销结果又驱动下一轮求解器更新现金与
欠款容量（撤销额回到发票欠款，**绝不**变成新现金）。因此不能把退票简单净额化
后只求一次最终流，也不能每轮重新分配此前已入账的切片。

## 报告

`schema_version` 为 5。顶层附 `ledger_sha256`（账簿原始字节 SHA）与
`source_sha256`（规范语义输入 SHA：invoice_refs 按 `(due_rank, id)`、eligible
按发票优先序规范化，events 保持原顺序；因此相同输入及仅调换
invoice_refs/eligible 顺序产生逐字节相同的 JSON 报告）。`result` 含：

- `invoices`：绑定所选发票 SHA 的冻结应收清单（优先序）；
- `events`：每事件之后的现金/欠款快照（逐来款 cash/returned、逐发票
  paid/debt）——可观察的事件前缀结果不受后续事件影响；
- `settles`：每次 settle 的目标向量 `[总额, 逐发票...]`（优先序）与非零矩阵；
- `slices`：原始核销切片（原额、累计撤销、有效余额、逐次撤销记录及来源事件）；
- `final`：最终逐来款（principal/returned/cash/reconciled）与逐发票
  （receivable/paid/debt）余额。

## 设计说明：历史切片与可重排空间如何共存

**不可重排的历史**是只增不改的事实链：切片一旦入账就携带固定身份（settle 事件、
来款、发票、原额），此后唯一合法的变化是被退票按 mandated 顺序部分或全部撤销，
且每次撤销都记下来源事件。**当前可重排的核销空间**只有三样：各来款此刻的未核销
现金、各发票此刻的剩余欠款、eligible 边集。两者只在容量处相接——settle 把现金
变成新切片（空间随之收缩），return 把有效切片变回发票欠款（空间随之变化），
已入账切片本身从不重新进入求解器。由此每轮 settle 都是在一个全新的、由历史
唯一决定的小图上求解，而历史切片谱系保持不可变且可审计。

**精确多层优先序的实现**：每次 settle 先以一次最大流（Dinic）求出本轮总额上
限；随后按"逐条固定"的方式做字典序优化——第二级按发票优先序、第三级按
（来款出现顺序 × 发票优先序）展平序，对每条边计算"在保持已固定边不变的前提
下，该边流量还能增加多少"，即残量网络中以该边为闭合边的最大循环流（已固定的
边从残量图中移除；第二级时未固定的汇边仍可反向让路，第三级时全部汇边固定、
源边双向可用因为来款行和从不作为目标固定）。字典序最大化的定义本身就保证
逐分量贪心是精确的；每次固定都是一次精确最大流，不是近似。全部算术为任意
精度整数：容量哨兵取 10^30（高于任何可达流量），不把大额整数转换成浮点费用，
也不用固定宽度会溢出的折叠权重。

**正确性义务**：本设计必须（a）在每个事件后同时满足两类守恒；（b）保证报告
的每个可观察前缀与只重放该前缀的结果一致；（c）保证三级目标的结果与求解路径
无关（字典序最大元唯一）；（d）保证撤销顺序精确落到切片身份上。测试以独立
枚举全部合法矩阵核对三级目标、以逐事件守恒和切片身份核对生命周期、以
"退票在首次 settle 前/后"的对照场景核对联动。

**另一种可行设计及其不同义务**：可以把每笔来款的退票即时净额化、在报告时只求
一次最终流（或每轮把全部历史切片重新投入优化器）。那样实现更简单——只需证明
最终状态最优——但它承担的是另一组义务：它无法给出逐事件现金/欠款快照，违反
前缀可观察性；切片没有稳定身份，退票无法"按原 settle 逆序、发票 id 降序"归属
到具体切片与来源事件，可追溯性随之丢失；每轮重优化历史还必须额外证明"改写
历史不产生可观察差异"。本仓选择保留不可重排的历史切片谱系，正是为了把审计
义务（每笔撤销可归属、每个前缀可重放）置于求解便利之上。

## 正确性与资源代价

- 每次 settle：1 次最大流 + 每张发票 1 次 + 每条 eligible 边 1 次残量循环流，
  图规模为 2 + 来款数 + 发票数（≤122 点、≤1440 弧），10 次 settle 总计
  ≤6600 次小图最大流；与金额大小无关，绝不按货币单位展开。
- 退票撤销为 O(该来款切片数)；每个事件后做完整守恒自检。
- 上限内完整支持：60 发票、60 来款、600 条 eligible 边、200 事件、10 次
  settle、10^18 大额，全部精确整数，仅用标准库。
